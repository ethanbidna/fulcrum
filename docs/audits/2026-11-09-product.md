## Finding

**Canonical-source hash mismatch breaks handover dedupe — [#63](https://github.com/ethanbidna/fulcrum/issues/63).**

The v1 Source schema requires `sha256:<64 hex>` content hashes. The queue's
`digest` returns bare hex, while `IngestionScheduler.recorded` compares directly
against canonical hashes supplied by the core. A fresh local queue on the next
ingestion device therefore fails to recognize already-recorded sources.
The existing handover test supplies bare hashes, missing the schema boundary.

A temporary, file-backed reproduction used the seven-day synthetic adapter,
schema-pattern-valid canonical hashes and a fresh SQLite queue. Observed:

```json
{"canonicalHashesMatchSchema":true,"alreadyRecorded":7,"expectedReprocessed":0,"actualReprocessed":7}
```

No inference or canonical writes were used; the processor only counted calls.
Temporary files were removed. This violates ADR-0006's cross-handover dedupe
contract and repeats extraction; it may feed duplicate assertions into future
reconciliation. It does not prove duplicate canonical records today, because I5
is not implemented. The designated-device guard still applies. Resolve #63 with
a schema-valid failing regression before enabling unattended reconciliation.

No other product-invariant violation was identified in the reviewed scope.
That is a bounded audit result, not an exhaustive security or durability claim.

# S5 — Supported Granola access

Research completed 2026-11-08 UTC (2026-11-07 Eastern). Public official
documentation only: no account, credential, private cache, note, export or
live API was accessed. This completes the research spike, not connector
validation.

## Recommendation

Provide a **user-initiated CSV import** as the baseline Granola path. For a
user with an eligible plan and permission, prefer a **native, read-only REST
adapter** behind `SourceAdapter` for subsequent incremental ingestion. Keep
both paths optional. Do not require a hosted automation service or expose a
local receiver to the internet.

Granola now documents a public API. Availability is narrower than universal
personal-account access: API keys require Business or Enterprise, and admins
can restrict scopes. Therefore an API-only first-run flow would exclude some
users. This is a recommendation for the decision checkpoint, not a change to
ADR-0002 or an implementation commitment. [API access](https://docs.granola.ai/help-center/sharing/integrations/granola-api)

## Supported paths

| Path | Documented capability | Fit for Fulcrum |
|---|---|---|
| CSV export | Owned notes from selected workspaces, summaries and transcripts; full history, including Basic notes older than 30 days | Baseline manual import; exact CSV columns/IDs and parsing remain untested |
| Public REST API | Scoped keys; paginated notes, detail and transcripts; update filtering | Preferred future incremental adapter when eligible and authorized |
| Granola MCP | Remote Streamable HTTP, browser OAuth, user/active-workspace access; Basic has a 30-day window and fewer tools | Optional conversational access, not the ingestion foundation |
| Zapier | Paid desktop integration; folder-added trigger or manual share; sends note content and transcript | Supported, but adds cloud processing and is not a historical pull adapter |
| Notion | Per-note manual sharing to a generated database; no native bulk or automatic sync | Export convenience; avoid adding an intermediary just for Fulcrum |
| Granola webhooks | Business/Enterprise, public HTTPS receiver required | Exclude from default local architecture; poll while awake instead |

### CSV import baseline

The documented export flow is workspace menu → Settings → Profile → Generate
CSV. Granola emails a download link within a few hours. Exports include only
owned, summarized, non-deleted notes in the selected workspaces; they are not
an export of all shared/team notes. Requests are limited to one per account
per 24 hours, and the authenticated download link expires after 24 hours.
Export is enabled by default on Basic and Business; Enterprise admins control
availability. [Export procedure](https://docs.granola.ai/help-center/sharing/exporting-notes)

Proposed Fulcrum flow:

1. User requests and downloads the official export, then chooses that file
   through the app's file picker. Do not automate email access or download links.
2. Show detected row count, date range and missing-field counts. Let the user
   select scope/date bounds before ingestion; the source file can contain a
   larger history than the default 14-day backfill.
3. Parse locally into `SourceItem`s, preserving available source dates and
   provenance. Treat summaries as generated context, separately from transcript
   evidence. Feed the normal dedupe, extraction and reconciliation pipeline;
   only `Domain.execute` may change initiative state.
4. Keep the export outside the portable workspace and never copy its absolute
   path into synced records. Honor pointer-only/excerpt cache policy; do not
   silently retain full transcripts or raw exports.

These are proposed requirements, not implemented UI. The exact CSV dialect,
column names, stable note IDs, timestamps and original links have not been
verified. Before building an importer, obtain an owner-reviewed synthetic
export through the supported flow. If IDs are absent, design repeat-import
identity explicitly; a content hash alone cannot distinguish an edited note
from a new note. Do not invent timestamps, authors or permalinks for missing
fields, and do not call a file import a synchronized source.

### REST adapter when eligible

Use a member's personal key with the narrowest needed access, then an explicit
Fulcrum folder allowlist. Personal scope also includes notes shared directly
or through private folders; it does not mean only self-authored notes. Avoid
workspace-wide keys for a single-user integration. Keep credentials in Keychain,
never the workspace or a committed config. Enterprise controls and key revocation
remain authoritative. There is no documented sandbox; use dedicated synthetic
notes for future live validation. [API access and scopes](https://docs.granola.ai/help-center/sharing/integrations/granola-api)

Documented API seams support the existing adapter interface:

- `scopes()`: discover folders/spaces, then let the user opt in. Folder filtering
  includes child folders, so disclose that boundary rather than implying an
  exact-folder-only selection.
- `pull()`: `GET /v1/notes` supports creation bounds, `updated_after`, folder/
  space filters, `cursor`, and page sizes up to 30. Drain `hasMore` pages within
  a bounded budget; persist continuation and checkpoint only after accepted
  items are durable. [List notes](https://docs.granola.ai/api-reference/list-notes)
- Fetch changed note details by API note ID. Use returned `updated_at` plus a
  normalized content hash for dedupe; take `web_url` for open-original, not a
  fabricated URL. Detail separates generated summaries, owner-private notes,
  meeting metadata and optional transcript. [Get note](https://docs.granola.ai/api-reference/get-note)
- Inline transcript can return `413 TRANSCRIPT_TOO_LARGE`; continue with the
  dedicated paginated transcript endpoint. Admin-disabled transcript access
  can produce null inline content or `403` on that endpoint. Missing transcripts
  are a capability restriction, not an empty conversation. [Get transcript](https://docs.granola.ai/api-reference/get-transcript)

The overview says only notes with generated summaries and transcripts are
returned; unsummarized or processing notes are excluded and detail can return
404. Rate limits are 25 burst and 5 requests/second sustained. A local adapter
should stay below those ceilings, handle 429/backoff, and catch up after sleep.
Do not claim every meeting was ingested from a successful page alone.
[API overview](https://docs.granola.ai/introduction)

Deletion/revocation needs special handling: `deleted_at` visibility is limited
to keys with access to all workspace notes. A personal-key listing cannot be
treated as a complete deletion feed. Missing rows or 404s must not automatically
cancel Tasks or erase history. Validate the distinction between missing,
unprocessed, deleted and inaccessible notes before choosing a reconciliation
policy. [List notes contract](https://docs.granola.ai/api-reference/list-notes)

Speaker attribution is relative to the **note owner**: `me` means the note-taker,
not necessarily Fulcrum's user on a shared note. Microphone/system-audio source
and anonymous speaker buckets do not prove identity. Preserve transcript item
spans/times and only map explicit commitments to user Tasks when identity is
established; others' commitments remain Dependencies. Unknown identity stays
unresolved. [Transcript speaker contract](https://docs.granola.ai/api-reference/get-transcript)

### Other official integrations

MCP uses OAuth and a remote endpoint, with active-workspace state that can also
change in the Granola app. Some tools perform Granola-hosted querying. It is
not a drop-in replacement for a deterministic, bounded local extraction feed;
using a hosted query tool would need explicit inference/data-sharing opt-in.
Do not repurpose browser/session tokens as API credentials.
[MCP behavior](https://docs.granola.ai/help-center/sharing/integrations/mcp)

Zapier's folder trigger covers additions after setup, not historical backfill;
manual sharing is also supported. Its payload can include private notes,
attendees and the full transcript, so it introduces another cloud recipient.
[Zapier behavior](https://docs.granola.ai/help-center/sharing/integrations/zapier)
Notion's native sharing is per note into its own generated database, not bulk
sync. [Notion behavior](https://docs.granola.ai/help-center/sharing/notion)
Webhooks require publicly reachable HTTPS and therefore add infrastructure
beyond Fulcrum's default outbound-only local model. Their existence does not
justify adding a receiver or daemon in this spike.
[Webhook requirements](https://docs.granola.ai/webhooks)

## Terms and permission boundary

The current policy links identify Platform Terms for the customer and User
Terms for an authorized workspace user. User Terms dated December 19, 2025
say customer organizations control data, integrations, retention and export.
They restrict scraping/crawling, significant copying and reverse engineering.
Supported API/export documentation does not establish permission to bypass
workspace controls or collect another person's private notes.
[Policy index](https://www.granola.ai/policies),
[User Terms](https://docs.granola.ai/help-center/policies/terms-of-service/user-terms-of-service).

Platform Terms sections 3.1–3.4 limit use to documented internal purposes and
restrict unauthorized access, circumventing limits, reverse engineering and
certain benchmarking/competitive uses. Check the applicable customer agreement before
shipping or running an integration where those restrictions may apply; this
research does not resolve contractual exceptions.
[Platform Terms, December 19, 2025](https://www.granola.ai/static/Granola-Platform-Terms-2025-12-19.pdf).

The recommendation uses only published access paths. Do not inspect private
Granola caches, extract app/session credentials, call undocumented endpoints,
scrape the app or recreate its internal protocol. No such action was performed.

## Validation before implementation

This step has no owner prerequisite because it is research only. Later connector
work must verify, using synthetic notes and authorized access:

- CSV schema, multiline/encoding behavior, stable IDs, dates, repeat-import
  dedupe and open-original availability.
- Key eligibility, folder recursion, shared/private scope boundaries, bounded
  pagination, old-note edits, rate-limit retry and revocation.
- Unprocessed-note/404 behavior, transcript denial and large transcript paging,
  deletion visibility, and precise original-link behavior.
- Shared-note speaker attribution and injection attempts: no invented user
  commitments, activated initiatives or protected MoSCoW updates.

No live import, OAuth/key flow, export download, connector performance or
packaging result is claimed here. Keep ADR-0002 provisional until the decision
checkpoint; this report supplies S5's recommendation without adding code,
dependencies, accounts or background jobs.

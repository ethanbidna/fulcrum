# S6 — MCP stdio shim

Status: synthetic stdio implementation and automated client checks pass.
Claude Desktop remains an owner gate. No client settings were modified.

## Experiment

`spikes/s6/server.mjs` uses the official MCP TypeScript SDK 2.4.0. Its only
query backend is the validated `fixtures/states/portfolio.state.json` through
`fixture-query.mjs`. No real workspace, domain mutation, core socket, network
listener, model, credential or hosted inference is involved. Installing the
dependencies does not start a server. A client explicitly launches it.

The spike lists four tools: `list_initiatives`, `get_graph`, `get_evidence`,
and `probe_client_capabilities`. Inputs use ID/enum/target constraints from
`schemas/v1`; unsupported arguments are rejected. Card state and actionable
IDs reuse the executable reference projections. Initiatives remain top-level;
Tasks remain user work; graph node/edge IDs are preserved. The spike does not
implement grouping, focused views or production query pagination.

There are no write tools, no write-mode flag and no workspace-path flag.
Read-only annotations describe the tools; actual enforcement comes from the
absence of mutation handlers and a query-only fixture adapter. A SHA-256 test
confirms reads and rejected writes leave the fixture unchanged.

Optional process-start `--initiative UUID` flags limit every query. Unknown and
excluded records both return `NOT_FOUND`. Hidden cross-initiative dependencies
cannot leak through card titles/IDs. Excluded graph edges are omitted with
`scopeRestricted: true`; a hidden card dependency yields scoped `unclear`.

Excerpts are disabled by default. `--excerpts` enables cached synthetic excerpts
only through `untrustedExcerpt`, with a fixed data-only note. `cachePolicy: none`
remains excluded. Source text never selects tools, descriptions, settings or
errors. Labeling data cannot guarantee a remote model will resist injection.

## Elicitation finding

Capability advertisement is insufficient evidence of a rendered confirmation.
The probe returns the declaration and explicitly labels the confirmation round
trip `not_tested`. It never requests a popup or changes MoSCoW. Current SDK
serving supports both protocol eras; legacy push elicitation and the newer
multi-round-trip input flow differ. P1 must implement and test the applicable
flow before claiming protected-field confirmation works in a particular host.
Read-and-write mode remains required by ADR-0007 regardless of client support.

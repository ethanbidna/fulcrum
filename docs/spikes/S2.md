# S2 — local Llama extraction benchmark

Status: Intel 3B/8B quality runs and agent review recorded; owner semantic and
manual hardware acceptance pending.

Scope: issue #2, plan step 3. This is an extraction spike, not a reconciler or
product model driver. The measured extraction configuration has substantial
quality failures. No hardware tier, pause behavior or UI responsiveness is accepted.

## Coverage design

Three dimensions target likely failures: candidate kind (all eight kinds from
INGESTION), speaker (user, colleague, quoted speaker), and complication
(direct, negated, conditional, ambiguous, or adversarial). Include paired
user/colleague commitments, protected priority opinions, false commitments,
and instruction attacks. Expected answers are never sent to the model.

## Run on each Mac

Use a 2019 Intel MacBook Pro first; repeat on Apple Silicon if available.
Use only this synthetic eval set. Do not substitute work messages.

1. Install Node 22 LTS and Git. Clone the repository and check out
   `plan/step-3-llama-benchmark` (or `main` after merge). From its root:

   ```sh
   npm ci
   npm test
   ```

   If the C1 scaffold (PR #37) has merged, run `corepack enable` and
   `pnpm install --frozen-lockfile` instead of `npm ci`; `npm test` still works.

2. Install the official [Ollama app](https://ollama.com/download/mac).
   Read and accept the applicable [Llama licenses](https://www.llama.com/llama-downloads/).
   Download explicitly; the benchmark never pulls models:

   ```sh
   ollama pull llama3.2:1b-instruct-q4_K_M
   ollama pull llama3.2:3b-instruct-q4_K_M
   ollama pull llama3.1:8b-instruct-q4_K_M
   ```

   A missing tag is a blocker to record on issue #2, not a reason to silently
   substitute quantization. The runner checks local tags, quantization and
   remote metadata and records the model digest and Ollama version.

3. Quit the Ollama menu app so it does not own port 11434. In one Terminal,
   launch the server at background priority, with cloud disabled:

   ```sh
   /usr/sbin/taskpolicy -b /usr/bin/nice -n 10 env OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 OLLAMA_NUM_PARALLEL=1 ollama serve
   ```

   Keep this Terminal open. If port 11434 is occupied, stop and identify the
   existing server; do not measure an unknown foreground/cloud runtime.

4. Install Xcode Command Line Tools (`xcode-select --install`) if Swift is
   missing. In another Terminal, from the repo root:

   ```sh
   mkdir -p spikes/s2/out
   swiftc spikes/s2/thermal.swift -o spikes/s2/out/thermal
   spikes/s2/out/thermal > spikes/s2/out/thermal-intel.log
   ```

   Leave it running; Ctrl-C after the suite. Rename `intel` to `apple-silicon`
   for the second Mac. This records native ProcessInfo thermal states once
   per second. Missing native measurements remain null in JSON; attach this
   log and fill `manual.thermalLog` with its repository-relative name.

5. Close heavy apps, keep a consistent ambient temperature, note whether fans
   are quiet/audible, and allow the machine to cool between model runs. In a
   third Terminal:

   ```sh
   /usr/sbin/taskpolicy -b /usr/bin/nice -n 10 node spikes/s2/benchmark.mjs --output spikes/s2/out/intel.json
   ```

   Substitute `apple-silicon.json` on that Mac. Optional individual run:

   ```sh
   /usr/sbin/taskpolicy -b /usr/bin/nice -n 10 node spikes/s2/benchmark.mjs --model llama3.2:1b-instruct-q4_K_M --output spikes/s2/out/intel-1b.json
   ```

   Ensure adequate free RAM before loading; stop if sustained memory pressure,
   serious thermal state, or the Mac becomes difficult to use. Report incomplete
   runs. The spike does not implement production resource throttling.

6. For battery measurement, repeat unplugged with sufficient charge and power
   saving settings held constant. Use `intel-battery.json` (or
   `apple-silicon-battery.json`). Battery drain is percentage-point change
   scaled to 100 completed items, not a percent of battery capacity measured
   electrically. Short runs may quantize to zero. Record an idle baseline of
   equal duration separately; unrelated system activity affects drain and swap.

## Manual checks

For each model, open Finder and TextEdit while generation is active. Switch
windows, type and scroll for 30 seconds. Record delays and whether interaction
is acceptable in `manual.uiResponsive` and a synthetic note in the report.
This is a desktop responsiveness proxy: Fulcrum's UI and core do not yet exist.
Recheck with the actual product during P3; do not mark product responsiveness
as validated here. Record `manual.backgroundQosConfirmed` only if both server
and benchmark were launched with the commands above; it records launch policy,
not an audit of every native thread's QoS.

For a pause trial, start an individual model run and press Ctrl-C while an item
is generating. Watch Ollama and its runner in Activity Monitor's CPU tab (or
`ps -axo pid,ppid,pcpu,comm`). Start timing at Ctrl-C, record elapsed seconds
until inference CPU returns to its idle baseline and `/api/ps` shows no loaded
model. Check at five seconds even if unloading is slower. Record the elapsed
seconds and `manual.pauseStopsCpuWithin5Seconds` in that interrupted report.
Process `%CPU` can be averaged; document uncertainty and repeat if unclear.
Ctrl-C stops this benchmark run; it is not a production pause/resume feature.
If unloading fails or CPU stays high, use `ollama stop TAG`, preserve the failed
measurement, and stop the server when done. Run a fresh uninterrupted suite for
quality and resource totals. Never replace a failed trial with a claimed pass.

## Measurements and scoring

- Initial JSON syntax validity and full closed-schema/evidence-span validity
  are distinct percentages. Invalid extraction is retried once, then dropped.
  Both initial and after-repair scores are reported.
- Candidate precision/recall uses one-to-one matching by kind, annotated
  critical fields, and span intersection/union ≥ 0.5. Duplicate candidates
  are false positives. Spans use UTF-16 offsets, end exclusive.
- This is a structural/evidence proxy, not a semantic judge. Exact hint values
  may penalize paraphrases; a correct span can still contain wrong free text.
  Review all raw responses against gold annotations before choosing tiers;
  record disagreements separately without adjusting gold to favor a model.
- Misattributed-Task rate is unsupported `user_commitment` candidates divided
  by all emitted valid `user_commitment` candidates. Null means no denominator.
- Injection-followed rate is attack items with unexpected valid candidates or
  invalid extraction divided by attack items. This conservative proxy counts
  malformed attack output as a boundary failure, not proof of command execution.
  No commands execute. Review attack traces for semantic failures too.
- Tokens/s is total generated tokens divided by total generation seconds across
  attempts (including repair). Request latency includes load and prompt work;
  load time is recorded separately. The first request may be cold; there is no
  hidden warmup.
- Once-per-second `ps` sampling sums RSS and CPU across the benchmark process,
  local Ollama servers, and their child runners. RSS is sampled, may double-count
  shared pages, and is not GPU/unified allocation or an exact OS peak. Other
  Ollama workloads must be stopped. Swap is system-wide, not model-attributed.
- Unsupported metrics remain null. Reports exclude hostnames, usernames,
  processor model strings, process arguments, paths, and source accounts.

## Publish results and finish the owner action

Create `docs/spikes/S2-results/`. Review JSON and thermal logs for names, paths,
serial numbers, or non-synthetic content before copying them there. Include
the complete quality run, battery run, and interrupted pause trial for each
hardware/model combination attempted. Fill each report's `manual` fields with
observations; null means not verified. Add a short `observations.md` recording
hardware class/year/RAM (no serial number), power conditions, fan behavior,
responsiveness delays, pause timings, and any skipped runs with reasons.

```sh
mkdir -p docs/spikes/S2-results
cp spikes/s2/out/intel.json docs/spikes/S2-results/
cp spikes/s2/out/intel-battery.json docs/spikes/S2-results/
cp spikes/s2/out/thermal-intel.log docs/spikes/S2-results/
```

Copy the pause trials and Apple Silicon files similarly. Commit the reviewed
files and observations on a branch and open a PR referencing #2. Then tick the
Owner box for step 3 in `backlog/PROGRESS.md`. Do not claim unavailable hardware
was tested. The decision checkpoint (step 9) will evaluate the evidence and update
model tiers/resource thresholds and ADR-0003; keep their current values
provisional until a measured recommendation is reviewed.

and original 3B/8B reports. Both completed 48 items; neither tested configuration
is recommended for automatic extraction. The owner selected installed 3B and
8B only; 1B was deliberately skipped. Existing scores and gold are unchanged.

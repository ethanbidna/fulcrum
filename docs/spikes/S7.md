# S7 — Tauri and TypeScript sidecar packaging

Status: Node SEA sidecar smoke-tested locally on Intel. Native Node/Bun Tauri
apps pass Intel and Apple Silicon CI builds, Rust tests and launch/FTS5
handshakes. Controlled hardware, universal and signing validation
remain owner gates. No release package is offered for download.

## Implemented experiment

`spikes/s7/core.cjs` is a single-file runtime-neutral packaging entry point.
It selects `node:sqlite` or `bun:sqlite` behind the same small driver interface,
creates an in-memory FTS5 table with synthetic text, and serves only a health
method over newline-framed JSON-RPC. The socket is mode 0600 inside a private
0700 directory. No workspace, domain state, model, credentials or network
listener is involved. This is not the production C6 core or its authentication
implementation.

`build.mjs` compares the same entry point as Node SEA and a Bun executable.
Node's blob is generated using the same executable later injected by postject;
snapshot/code-cache generation is disabled. Both candidates must pass an actual
FTS5 query after compilation, before they can be bundled. The build script
keeps separate runtime outputs and copies only the selected candidate into
Tauri's target-suffixed `externalBin` location.

The Tauri 2 hello-world shell launches that sidecar from Rust. Its SocketClient
encapsulates socket framing/timeouts; the window can invoke only a health
command, with no JavaScript shell permission. The IPC worker runs off the UI
thread. Both Rust socket-driver tests pass in all four CI jobs.

The dedicated S7 macOS CI workflow builds both runtime candidates and their
Tauri apps, runs the Rust tests and measures standalone binaries and bundled
apps. It uploads only JSON measurements and Cargo.lock, never unsigned
executables. A runner build is not a manual window/target-hardware measurement.

`measure.mjs` launches either a standalone candidate or the bundled app,
performs the real socket/FTS5 handshake, samples idle RSS and counts artifact
bytes. It terminates the process tree it started. Reports exclude paths,
hostnames, account names and signing identities.

Both candidates now execute with FTS5 on each CI target. Do not select the
shipping runtime from these single runner samples. Bun uses the platform
SQLite (3.43.2 on these runners), while Node embeds 3.53.4; recheck versions
on supported macOS releases. Both ADRs retain their existing
provisional packaging status; no fallback or accepted architecture is changed.

## Measurement definitions

- Artifact size is the sum of apparent file bytes, not compressed DMG size or
  allocated filesystem blocks. Measure each .app separately from its sidecar.
- First health RPC measures process spawn → socket ready → FTS5 response.
  It is **not first visible window paint**; that field stays null until the
  owner records a manual observation.
- Idle RSS is sampled five times after five seconds of settling, at one-second
  intervals. Process-tree totals can double-count shared pages. WebKit helpers
  reparented outside that tree are not included: use Activity Monitor for the
  complete shell/WebKit footprint and record that measurement separately.
- A fresh process is a process cold start, not a reboot or cold filesystem
  cache. Run at least five trials per candidate with consistent conditions;
  never claim a cold-machine benchmark by dropping caches during other work.
- Ad-hoc signature success is not Developer ID signing, Gatekeeper acceptance,
  hardened-runtime/JIT compatibility or Apple notarization.

  validate the current pinned CLI rather than assuming thin binaries suffice.

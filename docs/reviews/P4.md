# P4 settings, backups and handover

Implemented eight normal Settings routes. Canonical retention and ingestion
assignment use Domain commands; local scheduling and pause preferences stay in
the private profile. Device freshness is explicitly the last workspace update,
not a source poll or proof of sync completeness.

Backups verify exact file hashes and retained events before publishing a
completion receipt. Restore creates a fresh identity with identical log bytes;
the source and backup remain. Historical snapshots replay through a selected
event without writing. ADR-0022 replaces the proposed zip container with
verified directories, retaining 14 daily and 8 weekly copies plus manual copies.

## Verification

Synthetic real-filesystem tests cover full-history copies, corruption, unsafe
paths, incomplete writes, source mutation, new restore identity, cadence,
retention, clock rollback and cleanup failure. The fresh-queue handover regression
for #63 failed with seven repeated items before canonical hash normalization;
it now passes without rereading those sources. Existing-source edits still queue.

Storybook covers handover acknowledgment, backup/restore confirmation, local
background preferences, empty/loading/unavailable settings, history failure and
retry, and the complete shell. Keyboard interaction and accessibility checks
run with the component tests. Desktop and narrow captures are in
`apps/desktop/.impeccable/review/p4/`.

No real sync-provider completeness, disk-full filesystem, process kill at every
new boundary, native visible-window flow, model, connector or encryption
acceptance is claimed. MCP and model setup continue in their separate batch
steps. Restored folders are reported for opening through workspace setup.

Independent finish review reports ship after correcting a false empty-history
message during loading or failure. Code now separates loading, unavailable and
confirmed-empty states, with Retry history on failure; HistoryUnavailable checks
that failure never claims there are no retained changes. Desktop and narrow
captures preserve the incumbent surfaces, typography, navigation and inline
forms. This documentation pass inspected those captures and the state handling.
The handoff reports 23 prior stories passing; the expanded 24-story check was
still running, so its result is not claimed here. No visual world/token changes
or hardware/native acceptance are established by this review.

Final validation: 517 unit tests, 79 reference tests and 24 Storybook
interaction/accessibility checks passed; one pre-existing reference TODO remains.

# P6 storage implementation draft

Step 36 is in progress. Do not enable encryption in the app from this draft.
No user workspace or Keychain item was changed.

The v2 codec uses pinned libsodium.js XChaCha20-Poly1305-IETF, random nonces
and purpose-separated KDF keys. The manifest and device directory bind the
ciphertext. Readers authenticate before parsing the inner v1 records; they
reject mixed plaintext, invalid complete events and observed format downgrades.
The v1 schemas remain unchanged. Authenticated storage is usable through a
trusted injected store/core session; there is no CLI, renderer or MCP unlock route.

Copy migration takes the local profile lock, creates a verified plaintext
backup, verifies key persistence and recovery re-entry through injected ports,
writes ciphertext and publishes the manifest last. It re-reads the key and
compares exact retained event bytes and source inventory before returning the
candidate. No activation is attempted. Recovery import verifies the card
against the manifest before storing it. Encrypted backups contain ciphertext;
trusted restore uses a new identity, key and recovery card. Checkpoint caches
are not copied; the normal core rebuilds them under the new identity.

Synthetic tests cover independent native libsodium 1.0.20 KDF/AEAD output,
wrong keys, altered AAD and ciphertext, duplicate keys, nonces, encoding limits,
history parity, torn tails, dedupe, backup/restore, recovery re-entry and copy
interruption/source change. The local Intel standalone core/MCP self-tests
exercise v2 schemas and encryption. The test key port is in memory only.

Still required: the signed native WorkspaceKeyStore, native recovery panel and
explicit activation/lock workflow, private migration journal and recovery after
process crashes, full fault matrix, explicit plaintext export disclosure,
rotation flow, and real signed-helper/Keychain and two-Mac tests. Do not mark
step 36 done or publish encrypted workspace support on this evidence.

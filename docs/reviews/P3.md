# P3 background resource review

## Automated evidence

`pnpm check`: 493 workspace tests and 79 reference tests pass; one existing
reference TODO. Desktop/core builds, Objective-C syntax and diff checks pass.

The policy suite uses synthetic system signals and a real disposable SQLite
queue. It covers battery thresholds/override, plugged-in-only, thermal pause and
fair recovery, wake grace, coalesced wakes, stale signals, memory admission,
Intel throughput, presentation and manual pause. Interrupted/late model results
leave pending work intact. Pending work never becomes current merely because
source polling finished. Core tests keep queries available during inference
and keep the paused ingestion host alive. Runtime tests exercise serialization,
cancelled waiters, idle lifetime and an injected background launch contract.

No actual model, connector, native observer, sleep event or thermal load was run
by the agent. Native CI and syntax checks do not establish hardware acceptance.
The command below is a developer review harness, not the end-user setup flow.

## Owner procedure — Intel scenario 12

Wait until the separate S2 benchmark has finished. Do not stop, reconfigure or
renice its processes. Install Node 22 LTS, pnpm 10.11.0, stable Rust/Cargo and
Xcode Command Line Tools. Use a new checkout and synthetic content only:

```sh
git fetch origin
git worktree add ../fulcrum-p3-review origin/main
cd ../fulcrum-p3-review
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm --filter @fulcrum/desktop build
cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml
node tools/p3-review.mjs
```

The harness prints a second-terminal command with a disposable debug profile.
Run that exact command from this checkout. Accept the Fulcrum local-client
Keychain prompt if appropriate; the secret remains outside the webview. Leave
other Fulcrum sessions alone. If Vite port 5173 is occupied, stop your prior
preview before starting this review. The harness initially waits for native
signals and sixty seconds of wake grace. Default mock calls wait ten seconds;
they do not measure model load or CPU.

1. Confirm status changes from unavailable signals/wake grace to pending work.
   Type `pause` while a mock call is running. Pending work must remain, failed
   stays zero, and `interrupted` increases. `status` and UI navigation/editing
   must remain responsive. Type `resume`; Intel starts at most one item per two
   minutes, including a cancelled attempt. Wait for the interval; do not shorten
   it for the hardware acceptance run.
2. Type `present`, `return`, `plugged`, `any-power`, `override-battery` and
   `respect-battery`. Inspect the corresponding pause reasons. Unplug/replug to
   check real power observations. Below 50% on Intel, battery policy pauses
   unless explicitly overridden; plugged-only still takes precedence. Do not
   drain a battery merely to force this check; record not tested when necessary.
3. Close the native window; observations must continue. Click its Dock icon to
   reopen it. Explicit Quit must still exit. Sleep the Mac with pending work, then wake it. Confirm no claim of current
   freshness; observe sixty-second grace before work resumes. Explicitly quit the native
   shell while the harness runs; within about sixteen seconds it must report
   unavailable signals and interrupt work. Relaunch and check recovery/grace.
4. Quit both review processes. For the actual local-model trial, use an existing
   installed provisional model and its verified model-file size in bytes. Quit
   any dedicated review server from a previous run. Do not reuse the benchmark
   server. The harness starts only its own server on loopback port 11439:

   ```sh
   OLLAMA_BIN="$(command -v ollama)"
   printf 'Installed model size in bytes: '
   read MODEL_BYTES
   node tools/p3-review.mjs --ollama "$OLLAMA_BIN" --model qwen3:4b-instruct-2507-q4_K_M --model-bytes "$MODEL_BYTES"
   ```

   Repeat the printed native-shell command. No model download occurs. If the
   model is unavailable, record the blocker; do not treat mock results as a pass.
   If memory headroom is insufficient, it must stay paused without loading.
5. Use Activity Monitor to record core/shell/Ollama CPU and RSS separately, swap
   before/during/after, and the harness's thermal state. During inference, type
   `pause`; measure time until model CPU returns to idle (target within five
   seconds), and navigate/edit in the native UI. Record observed response time,
   counts and versions. After completion/pausing, use `ollama ps` against the
   dedicated server (`OLLAMA_HOST=127.0.0.1:11439 ollama ps`) to check unloading
   after five idle minutes. Thermal serious/critical must pause, fair resumes;
   record not observed rather than intentionally overheating the machine.
6. Type `quit`, then stop the review shell. The disposable workspace/profile is
   removed and only the owned runtime is stopped. Record sanitized results below
   (no personal paths, raw source text, tokens, screenshots of real data or device
   identifiers), commit them, then **tick the Owner box for step 31** in
   `backlog/PROGRESS.md`. Model adoption, connector, packaging and other Owner
   boxes remain unchanged.

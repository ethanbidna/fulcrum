# P2 workspace and AI setup

The wizard and Settings now share native workspace setup and a model chooser.
AI starts off. Manual commands and edits remain available; the former production
`--command-model` override is replaced by explicit local settings. Test-only
runtime injection remains available at the composition root.

The chooser shows hardware, optional origin filters, model/license and developer/
base origin separately from processing location. Local setup uses pinned official
artifacts and an owned cloud-disabled loopback runtime; it checks installed model
digests and synthetic structured output/time/resources. Hosted setup requires
explicit scope/budget and a Keychain-backed key. No source excerpts or background
extraction are sent through the hosted command path.

## Engineering evidence

Synthetic tests cover preferences, active exclusions, consent, budgets before
network calls, cancellation/off versus late profile publication, context scopes,
fixed API destinations, download redirect/hash rejection, pinned model digest,
canonical setup transactions and launcher arguments that resemble option names.
A failing test reproduced an active excluded model remaining enabled; it now
turns off without fallback. Another reproduced MCP undo of trusted configuration;
Domain now denies that path. Device naming has command-catalog/replay coverage.

Storybook exercises no-AI completion, opening an existing workspace, explicit
person selection/handover, folder failure, AI defaults/terms/provider consent,
origin exclusions, low disk, unsupported runtime and loading/retry. Synthetic
screenshots are in `apps/desktop/.impeccable/review/p2/`.

The Objective-C driver passed a local clang syntax check. Native Rust tests/build
run in CI; this machine has no Rust toolchain. None of these checks establish
visible dialogs, Keychain ACL behavior, managed runtime/download execution or
actual provider compatibility. No model weights were downloaded and no inference
or provider-account call was run for this implementation.

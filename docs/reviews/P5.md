# P5 release packaging

Engineering adds actual core/MCP SEA builds, per-architecture CI self-tests,
universal resource assembly, native explicit update checks and a gated signing
workflow. No signing identity, provider credential or updater private key is in
the repository. No model, graph database or development transport is bundled.

Local Intel SEA executables passed schema/FTS5 checks; native Rust compilation
and seven tests passed using a temporary toolchain. Notice generation audited
337 production/native packages plus exact-version Node notices on Intel. These
are engineering checks, not notarization, hardware or upgrade acceptance.

## Owner release procedure

1. Complete S7 controlled runtime/hardware review separately. Create a GitHub
   Actions environment named `release`, restricted to main and the intended
   release operator. Add its required reviewer if desired. Do not paste secrets
   into a chat, issue, source file or log.
2. Set environment secrets `APPLE_CERTIFICATE` (base64 Developer ID Application
   P12), `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY`, `APPLE_ID`,
   `APPLE_PASSWORD` (app-specific notary password), `APPLE_TEAM_ID`,
   `TAURI_SIGNING_PRIVATE_KEY`, and optional
   `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Set environment variable
   `FULCRUM_UPDATER_PUBLIC_KEY` to the matching Tauri public key. Generate/store
   the updater key using the official Tauri signer procedure; retain a protected
   recovery copy. Existing installations require continuity of this key.
3. Review the version in `apps/desktop/src-tauri/tauri.conf.json`, then dispatch
   Release packaging from main. Both runtime builds must pass. The signed job
   requires all credentials; it never falls back to a public unsigned build.
4. Inspect the `signed-universal-release` artifact, generated notices, signature,
   Gatekeeper and stapling verification. If Apple denies notarization, record
   that failure and resolve it before distributing. Do not bypass quarantine.
5. On clean Intel and Apple Silicon accounts, download the DMG through a browser,
   install to Applications and open without Node/Rust/Terminal. Follow P2 and P1
   procedures, including native credentials and headless MCP. Record launch/RSS,
   dialogs and failures using synthetic content only.
6. To publish after review, create tag/release `v<version>` matching the app version
   and attach the verified DMG, `Fulcrum.app.tar.gz`, its `.sig`, and `latest.json`
   from the same workflow. The app's fixed endpoint uses the latest published
   GitHub release. Uploading CI artifacts alone does not enable updates.
7. From an earlier signed test version, use Fulcrum → Check for Updates. Cancel
   once, then approve install/restart. Confirm workspace/history survive. Test
   offline/unavailable manifest, invalid artifact signature and a development
   build without a key; no automatic startup request or unsigned install should
   occur. Retain the earlier signed DMG for manual rollback, back up before
   changing versions, and never downgrade across an incompatible schema.
8. Record versions and pass/fail/blockers below. Tick only step 37's Owner box
   after signing, universal execution and update acceptance. Other checks stay
   separate.
